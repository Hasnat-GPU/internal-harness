01 System Definition, Hardware Profile & Harness² Stack Position

The Internal Harness sits directly beneath Harness² (Tier 1) and above the Frozen Cloud LLM API (Tier 3). Instead of stuffing past mistakes and prompt edits into an ever-growing text window, Harness² delegates its continual learning to a compressed local Edge AI model whose plastic weights evolve on every verified refinement.

02 Core Engineering Solutions for Continual Learning & Laptop Efficiency

Explicit architectural mechanisms solving Cold-Start bootstrapping, Contradictory Rule unlearning, Bad-Habit Poisoning, and Battery/Thermal preservation.

1. Progressive Anchor Bootstrapping (Cold-Start Fix) SOL-COLDSTART

Solves how data/anchor_eval.jsonl is populated on Day 1 without blocking sleep cycles:

  • Stage 1 (Day 1 Seed): Ships with 12 immutable core Harness² invariant rules (3 per domain tag) in data/seed_anchors.jsonl.
  • Stage 2 (Auto-Promotion): Whenever an event in episodic_buffer.db has is_human_correction == 1 OR achieves verified_success_count ≥ 3 in Harness², it is automatically promoted into anchor_eval.jsonl.
  • Stage 3 (Stratified Cap): Capped at 100 total rules (max 25 per domain tag). When full, new promotions replace the oldest non-seed anchor with the lowest surprise score.
2. Semantic Rule Superseding (Intentional Unlearning) SOL-UNLEARN

Prevents old rules in anchor_eval.jsonl from blocking newer contradicting workflows:

  • Conflict Detection: When a verified rule arrives at POST /v1/observe, compute mean-pooled last-layer embedding cosine similarity against active rules in the same domain_tag.
  • Auto-Deprecation Rule: If cosine_sim(context_new, context_old) ≥ 0.85 AND cosine_sim(action_new, action_old) < 0.50 (or if request sets supersedes_previous: true), mark the old SQLite record status = 'DEPRECATED'.
  • Anchor Eviction: Deprecated rules are immediately purged from anchor_eval.jsonl so Sleep Consolidation distills the new rule without KL/regression conflict.
3. Two-Stage Contrastive Outcome Filter (Anti-Poisoning) SOL-OUTCOME

Ensures the Edge AI never trains its weights to memorize tool crashes or broken prompts:

  • Stage A (Quarantine Raw Failures): If outcome_status == "FAILURE", the Surprise Gate computes $S_t$ for telemetry but locks weight updates and writes the failure to table pending_failures.
  • Stage B (Verified Resolution Update): Weight updates in M3 execute only when outcome_status == "VERIFIED_SUCCESS" or is_human_correction == 1.
  • Contrastive Unlikelihood Step: If the success resolves a prior pending_failures row, loss includes a negative unlikelihood term: $\mathcal{L}_{total} = \mathcal{L}_{CE}(y_{good} \mid x) + 0.2 \cdot \log P(y_{bad} \mid x)$ to actively push weights away from the failed pattern.
4. Silent Zero-Idle & Event-Count Sleep Trigger SOL-THERMAL

Guarantees cool, quiet laptop operation on battery or wall power:

  • Zero Background Polling: No cron loops or background threads. When Harness² is idle, the Internal Harness consumes 0.0% CPU and ~1.1 GB static RAM.
  • Event-Count Sleep Trigger (Option B): Consolidation never wakes the laptop at night. It triggers strictly when unconsolidated_count ≥ 100 verified events OR when explicitly called via POST /v1/sleep.
  • Top-8-Layer Micro-LoRA + 4-Thread Cap: Freezing the bottom 16 layers of the 24-layer Edge model avoids 66% of backward-pass activation storage and keeps CPU updates under 110 ms on 4 threads.

03 Multi-Layer Security & Weight-Integrity Architecture

Because Harness² modifies system prompts, tools, and subagents, the Internal Harness enforces four mandatory security gates before any text or gradient touches disk.

SEC-01: Pre-Tokenization Secret & PII Scrubber src/security/scrubber.py
  • Deterministic Regex + Shannon Entropy Filter: Scans all incoming context_text and expected_action payloads before SQLite storage or tokenization.
  • Redacted Patterns: OpenAI/Anthropic/Google keys (sk-..., AIza...), GitHub PATs (ghp_...), AWS tokens, Bearer headers, private SSH keys, IPv4 addresses, emails, and high-entropy strings ($H > 4.5$ bits/char over $\ge 24$ chars).
  • Replacement Token: Replaces matches with canonical placeholder <REDACTED_SECRET> so secrets are never baked into .safetensors weights.
SEC-02: Indirect Prompt-Injection & Weight Firewall src/security/firewall.py
  • Trust-Level Tagging: Every event carries source_trust: Literal["HUMAN", "HARNESS2_VERIFIED", "UNTRUSTED_EXTERNAL"].
  • Hard Rule: Events tagged UNTRUSTED_EXTERNAL (e.g., raw scraped web pages or third-party MCP tool outputs) are blocked from opening the Plasticity Gate until validated by a Harness² critic pass.
  • Instruction-Override Scanner: Blocks weight updates containing adversarial override phrases (e.g., "ignore previous instructions", "curl / wget external IP", "disable safety gate").
SEC-03: Cryptographic Weight Manifest & SafeTensors Lock src/security/integrity.py
  • Zero Pickle Execution: Strictly forbids torch.load() on .pt or .bin files. All adapters load exclusively via HuggingFace safetensors (memory-mapped, zero arbitrary code execution).
  • SHA-256 Chain of Custody: Every write to weights/*.safetensors updates weights/manifest.sha256. Before every inference or sleep cycle, the loader verifies the SHA-256 checksum; on mismatch, it halts and restores the last verified snapshot.
SEC-04: WSL2 Loopback Isolation & Token Auth src/server.py
  • Network Binding: Uvicorn server binds exclusively to 127.0.0.1:8420 (or local Unix socket /tmp/internal_harness.sock with permissions 0600).
  • Shared Secret Header: Requires HTTP header X-Harness-Token matching the 256-bit random token in .env on every request to /v1/observe, /v1/infer, and /v1/sleep.

04 Six Core Modules (Explicit Specifications & Contracts)

M1: Secure Event Ingestor & Normalizer mod_ingest
File Path:src/ingest/normalizer.py
Responsibility:Validates Harness² payloads, runs SEC-01 (PII/Secret Scrubber) and SEC-02 (Injection Firewall), checks semantic conflict against existing rules, and tokenizes up to 1024 tokens.
Domain Tags:prompt_refinement | tool_synthesis | memory_policy | subagent_routing | general
Output:SanitizedEvent(input_ids, labels, domain_tag, outcome_status, supersedes_id)
M2: Surprise Sensor & Contrastive Gate mod_surprise
File Path:src/core/surprise_gate.py
Responsibility:Computes token-masked cross-entropy loss $S_t$ on target_action_tokens using the INT8 Edge model and enforces the Contrastive Outcome Filter (SOL-OUTCOME).
Gate Logic:OPEN if (outcome_status == "VERIFIED_SUCCESS" AND $S_t \ge 1.85$) OR is_human_correction == True. Quarantines raw failures.
Output:GateDecision(is_open, surprise_score, contrastive_loss_tensor)
M3: Top-Layer Micro-LoRA Fast Memory mod_fast_weights
File Path:src/memory/fast_weights.py
Responsibility:Updates Rank-8 LoRA adapters on the top 8 transformer layers (q_proj, v_proj) via 1–2 steps of AdamW ($ ext{lr}=1 ext{e-}4$, max grad norm $1.0$).
Persistence:Atomically writes weights/fast_state.safetensors (~3.2 MB) + updates manifest.sha256.
CPU Budget:60–110 ms on 4 threads of i9-13900H; automatic rollback on NaN/Inf.
M4: Episodic SQLite & Task-Vector Bank mod_bank
File Path:src/memory/vector_bank.py
Responsibility:Manages episodic_buffer.db, handles rule deprecation (SOL-UNLEARN), auto-promotes anchors (SOL-COLDSTART), and merges domain task vectors ($\Delta W = \sum w_k \Delta W_k$).
Domain Files:weights/domains/{prompt_refinement,tool_synthesis,memory_policy,subagent_routing}.safetensors
M5: Event-Count Sleep Consolidator mod_sleep
File Path:src/consolidation/sleep_daemon.py
Responsibility:Triggered when unconsolidated_count ≥ 100 or via POST /v1/sleep. Distills fast_state into long_term_state using 50% new events + 50% active anchors with KL tether ($\lambda = 0.4$).
Verification Gate:Requires $\ge 98\%$ pass rate on active anchor_eval.jsonl before committing weights.
M6: Mode-B Closed-API Policy Bridge & Critic mod_bridge
File Path:src/bridge/closed_api_bridge.py
Primary Path (Mode B):Generates a 150-token JSON Harness2PolicyEnvelope steering the Cloud API's system prompt, tool selection, and subagent routing, followed by a post-inference Surprise Gate verification pass.
Optional Path (Mode A):src/bridge/open_latent_bridge.py (Deferred to Optional Phase 6).

5.2 Explicit SQLite Schema (data/episodic_buffer.db)

CREATE TABLE IF NOT EXISTS episodic_events (
    event_id TEXT PRIMARY KEY,            -- UUID v4
    created_at INTEGER NOT NULL,          -- Unix epoch milliseconds
    domain_tag TEXT NOT NULL,             -- 'prompt_refinement'|'tool_synthesis'|'memory_policy'|'subagent_routing'|'general'
    source_trust TEXT NOT NULL,           -- 'HUMAN'|'HARNESS2_VERIFIED'|'UNTRUSTED_EXTERNAL'
    outcome_status TEXT NOT NULL,         -- 'VERIFIED_SUCCESS'|'FAILURE'
    context_text TEXT NOT NULL,           -- Scrubbed input state / task context
    expected_action TEXT NOT NULL,        -- Scrubbed verified refinement or action
    context_embedding BLOB NOT NULL,      -- Float32 mean-pooled vector for conflict check
    surprise_score REAL NOT NULL,         -- Cross-entropy loss S_t at ingestion
    is_human_correction INTEGER NOT NULL, -- 1 if human override, 0 otherwise
    verified_success_count INTEGER DEFAULT 1,
    status TEXT DEFAULT 'ACTIVE',         -- 'ACTIVE'|'DEPRECATED'
    supersedes_event_id TEXT DEFAULT NULL,-- Points to older event_id if replaced
    consolidated INTEGER DEFAULT 0        -- 0 = pending sleep, 1 = merged into long_term
);

CREATE TABLE IF NOT EXISTS pending_failures (
    failure_id TEXT PRIMARY KEY,
    created_at INTEGER NOT NULL,
    domain_tag TEXT NOT NULL,
    context_text TEXT NOT NULL,
    failed_action TEXT NOT NULL,          -- Stored for contrastive unlikelihood penalty once resolved
    resolved_by_event_id TEXT DEFAULT NULL
);
